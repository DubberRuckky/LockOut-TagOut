Zero-Trust Three-Factor Authentication Guide

Every login into the LockOut-TagOut gateway requires three cryptographic and biometric factors:

  1. Factor 1 (What you have): Cryptographic Device Keyfile containing an Ed25519 signing seed and a 32-byte HKDF shared secret.
  2. Factor 2 (What you know): Officer Passcode hashed via Argon2id.
  3. Factor 3 (Who you are): Live Biometric Face Presence verified via camera frame burst analysis.

How to Add a New Officer

Officers are provisioned using the lotoctl administrative binary. The gateway hot-reloads store.json automatically, so no server restart is needed.

Command Syntax

.\user_gateway\target\debug\lotoctl.exe user add <officer_id> --keyfile <keyfile_path> --passcode "<passcode>" --rank-tier <1-5>

Example: Enrolling Inspector David (Rank Tier 4)

.\user_gateway\target\debug\lotoctl.exe user add david --keyfile .\lot-data\david.keyfile.json --passcode "David123!" --rank-tier 4

Rank Tiers & Authorization Levels

  • Tier 1 — Constable: Deposit evidence files and propose case amendments.
  • Tier 2 — Head Constable: Deposit evidence files and propose case amendments.
  • Tier 3 — Sub-Inspector: Edit created cases and close/seal cases with SHA-256 hash trees.
  • Tier 4 — Inspector: Approve/reject amendments, initiate Tagout investigations, and approve system restore keys.
  • Tier 5 — Superintendent: Full executive administration, audit inspection, Tagout authorization, and dual-key system restore.

Dual-Control Restore Procedure

Restoring the system from LOCKED or TAGOUT requires two distinct officers of Tier 4 or higher within a 2-minute authorization window: 

# 1. Generate 2-minute restore authorization key
.\user_gateway\target\debug\lotoctl.exe generate-restore-key --out .\lot-data\restore.key.json

# 2. Execute dual-officer restoration
.\user_gateway\target\debug\lotoctl.exe restore --restore-key .\lot-data\restore.key.json --officer-keyfile .\lot-data\carol.keyfile.json --officer-keyfile .\lot-data\david.keyfile.json
